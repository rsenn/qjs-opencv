### cutpoly: none vs guided

A hand-written outline in fractions of the photo (a loose box; adjust the points to roughly circle a
subject with a soft or hairy edge for a real test):

```bash
P='[[0.30,0.20],[0.70,0.20],[0.75,0.50],[0.70,0.85],[0.30,0.85],[0.25,0.50]]'
opencv-imgproc cutpoly --in PHOTO.jpg --out /tmp/smoke/none.png   --mask-out /tmp/smoke/none-mask.png   --polygon "$P" --refine none
opencv-imgproc cutpoly --in PHOTO.jpg --out /tmp/smoke/guided.png --mask-out /tmp/smoke/guided-mask.png --polygon "$P" --refine guided
```

Each prints one result line ending `"ok":true`, with `"refine":"none"` / `"guided"`. View both on a checkerboard
and the difference of the two alphas:

```bash
W=$(magick identify -format %w PHOTO.jpg); H=$(magick identify -format %h PHOTO.jpg)
for n in none guided; do magick -size ${W}x${H} pattern:checkerboard /tmp/smoke/$n.png -compose over -composite /tmp/smoke/$n-view.png; done
magick /tmp/smoke/none-mask.png /tmp/smoke/guided-mask.png -compose difference -composite -auto-level /tmp/smoke/alpha-diff.png
```

Pass: `guided-view.png` follows the real edge of the subject (hair, petals) where `none-view.png` follows your
polygon; `alpha-diff.png` is bright only in a thin band along the outline and black everywhere else; the
inside of the polygon is fully opaque and everything far outside is fully transparent.
Fail: a halo or leak well outside the polygon, a hole inside, or nothing differing at all.

### edgemap: CLAHE off vs on, with timings

Use a badly lit photo (dim, or backlit):

```bash
opencv-imgproc edgemap --in DARK.jpg --out /tmp/smoke/e0.png --cache-dir /tmp/smoke/cache --clahe-clip 0 | tail -1
opencv-imgproc edgemap --in DARK.jpg --out /tmp/smoke/e3.png --cache-dir /tmp/smoke/cache --clahe-clip 3 | tail -1
```

Each ends with a line like `{"event":"result","ok":true,"command":"edgemap","output":{"path":...,"width":640,...},"detector":"none","provider":null,"cached":false,"timings":{...}}`. Run the same command twice: the second shows `"cached":true`.
Look at `e0.png` and `e3.png` side by side: the 3 version should show clearly more edges in the dark areas.

The wild-beauty browser ignores a map with under 0.3 % or over 60 % of pixels at red >= 64. Check the share:

```bash
magick /tmp/smoke/e3.png -threshold 25% -format "%[fx:mean*100] %%\n" info:
```

Pass: between 0.3 and 60. Typical photos should land well inside. I did not measure the 12 MP speed target
(under 0.5 s without a detector); check `timings.totalMs` on a big photo and tell me.

An unknown flag must fail: `opencv-imgproc edgemap --in PHOTO.jpg --out /tmp/x.png --claheclip 0` prints
`"code":"E_USAGE"` and exits 2.

**cuDNN blocker.** Your configure log stops at `DNN: CUDA backend requires cuDNN`. On Linux Mint 22.2
(= Ubuntu 24.04 noble) with CUDA 12.0 from the distro:

```bash
wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb && sudo apt update

```

Then re-run `cfg-cuda -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-12` (your g++ 16 is too new for nvcc 12.0)
and check the summary says `cuDNN: YES`. These package names are from memory, not verified. Do not blind
`apt upgrade` afterwards: NVIDIA's repo also has newer CUDA packages than your distro's 12.0.
If `libcudnn9-dev-cuda-12` is still not found: paste `apt-cache policy libcudnn9-dev-cuda-12`.

**Is CUDA really used?** Use a net-loading command with a fresh cache so it is not a cache hit:

```bash
# terminal 1
nvidia-smi dmon -s u
# terminal 2
time opencv-imgproc prepare --in PHOTO.jpg --model mobilesam --cache-dir /tmp/smoke/c-cpu  --dnn-target cpu
time opencv-imgproc prepare --in PHOTO.jpg --model mobilesam --cache-dir /tmp/smoke/c-cuda --dnn-target cuda
```

On the cuda run: stderr shows `"message":"dnn: mobile_sam_image_encoder.onnx on cuda"` (if it shows
`dnn: cuda not usable ... using the cpu`, paste that line), `nvidia-smi dmon` shows the `sm` column above 0
while it runs, and the time drops from the CPU's roughly 1.5 s for the encoder (my number from the code
comments, not measured on your machine). **The tool cannot see a silent fallback**: OpenCV may accept the
CUDA backend and still run unsupported layers on the CPU. If `sm` stays 0 and the times match, it
did not use the GPU.
